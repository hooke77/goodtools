# 小学英语朗读跟读小程序

> 沪教牛津版（2024 新版）六年级上册 · 微信小程序  
> 功能闭环：**朗读示范 → 开口跟读 → 逐词纠音 → 听写巩固 → 错题沉淀**  
> 适配**个人主体**小程序：不依赖任何插件，导入即可编译运行

---

## 一、它能做什么

| 环节       | 实现方式                                                                    |
| -------- | ----------------------------------------------------------------------- |
| ① 朗读一句课文 | 播放随包携带的示范音频（251 段，见 `audios/`），可反复听、可 **0.7 倍速慢放**，断网也能听                |
| ② 打开话筒跟读 | 调微信原生录音，录完自动进入对比                                                        |
| ③ 读错就纠正  | 接云端识别时做词级比对（逐词标绿/黄/红）；**默认的自评模式**下用「读前易错词预告 + 录音时长/示范时长节奏比对」给客观反馈（见第七节） |
| ④ 听写巩固   | **纸笔听写**（写纸上自己核）或**打字听写**（逐词自动判对错），题源是 41 句重点句型 + 94 个课本核心词（见第八节）       |
| ⑤ 记录高频错误 | 每课沉淀「错误句子榜」和「错误词语榜」，跨单元汇总，支持一键复制"待攻克清单"；朗读和听写的错题记在同一本账上                 |

另外附带：**单词跟读**（每单元核心词，带音标与搭配）、**自动下一句**（读准才过）、**句子列表**（看整段掌握度）、**A/B 对比**（示范与自己的录音连着播，差在哪一听就知道）、**音频自检**（首页一键确认声音通不通）。

内容规模：**6 个单元 / 125 句课文 / 94 个单词 / 41 句重点句型**。

## 二、⚠️ 先看这里：为什么没有用「微信同声传译」插件

网上几乎所有「小程序语音识别」教程都让你在 `app.json` 里加这段：

```json
"plugins": {
  "WechatSI": { "version": "0.3.5", "provider": "wx069ba97219f66d99" }
}
```

**个人主体小程序加这段一定编译失败**，报「没有权限」或「添加失败，小程序类目不符合要求」。

原因是硬规则：`微信同声传译` 插件的服务类目是 **IT科技 > 软件服务提供商**，  
而**该类目不对个人主体开放**。小程序使用的插件，其插件类目不能超过主体类型开放的范围，  
所以个人主体后台**连搜都搜不到**这个插件。（微信开放社区置顶问答、以及多个官方回复都确认了这一点；  
2022 年前个人主体还能用，之后收紧了。）

所以本项目的做法是：

- **朗读示范**：完全不用插件。预先用 TTS 生成 218 段 mp3 随包携带 → 个人主体可用、免费、离线、稳定。
- **跟读评分**：给了三条路，默认那条**零配置、零成本、个人主体直接能用**。

### 三种跟读模式

| 模式                | 怎么打分                                       | 需要什么                          | 适合谁           |
| ----------------- | ------------------------------------------ | ----------------------------- | ------------- |
| **`self` 自评（默认）** | 录音回放 + 「示范→我的」A/B 连播，孩子/家长判断；错词在句子上点选，照样入库 | 什么都不用                         | **个人主体，开箱即用** |
| `cloud` 云端识别      | 录音上传云函数 → 腾讯云一句话识别 → 端上评分纠音                | 部署 `cloud/asr-tencent`（含免费额度） | 想要机器自动打分      |
| `plugin` 插件识别     | 微信同声传译插件                                   | **仅企业/个体户等非个人主体**             | 有企业主体时        |

切换方式：改 `config.js` 里的 `ASR_MODE`。改成 `cloud` 后照  
[`cloud/asr-tencent/README.md`](cloud/asr-tencent/README.md) 走一遍就行（个人实名即可，每月 5000 次免费）。

> 自评模式并不是"功能阉割"：孩子练发音时，**「听示范 → 听自己 → 找差别」本身就是最有效的训练**。  
> 而且错句错词、错误率、均分这些统计一样都不少，报告页照样能生成「高频错误句子 Top 10」。

## 五、评分算法怎么算的

`utils/score.js` 完全在端上跑，不依赖后端：

1. **归一化**：转小写、去标点、把 `I am` 归并成 `I'm`（`do not → don't`、`cannot → can't`），避免课本写法和识别结果对不上。
2. **词级对齐**：对目标句与识别结果做 LCS 序列比对，支持"模糊相等"（同词首、编辑距离 ≤1/≤2）。
3. **吞音判定**（小学阶段最大痛点）：目标词只比说出的词多 1~2 个字母时（`pads→pad`、`wanted→want`、`slide→slid`）判为**词尾吞音**，直接算错。
4. **打分**：`词准率×78 + 字面相似度×22`，再按「漏读每个 −6 分、读不准每个 −2 分」扣分（最多扣 30）。
5. **评语防误伤**：只要有漏读或吞音，分数再高也不给"优秀"，而是明确告诉孩子"有 1 个词没读到"。

> 实测（`tests/score.test.js`）：`I'm` 与 `I am` 互读得 100 分；  
> `It makes…` 读成 `It make…` 得 86 分但会被标红并提示 `-s`；`ramp` 读成 `lamp` 判错。

## 六、错题是怎么记录的

`wx.setStorageSync` 本地存储，结构：

```
lessons.u1.sentences['u1-p1-s7'] =
  { en, cn, passageName, count, errorCount, avgScore, bestScore, lastScore,
    errorWords: { makes: 2 } }
lessons.u1.words['homeless'] =
  { en, cn, count, errorCount, lastScore }
```

- 判定"是否算错题"由 `storage.js` 统一负责：**只要漏读 / 吞音 / 多读，即使分数够高也计入错题**。
- 报告页按 `errorCount` 排序输出「高频错误句子 Top 10」和「高频错误词语 Top 12」，并显示错误率、均分、跨单元标记。
- 每条错句都能直接点「去练这句」跳回对应位置重读。

想改成**多设备同步**：把 `utils/storage.js` 里的 `getStore / saveStore` 换成云开发数据库读写即可，其余代码不用动。

## 七、自评模式：不接语音识别，也能给出反馈

默认的 `ASR_MODE: 'self'` 不调用任何识别服务，所以没有"逐词自动打分"。  
但空着让家长自己判断太浪费，这里补了**两条不需要云服务的客观反馈**：

### 1. 读前预告：先说清楚这句要留意什么

用严格版发音规则（`utils/tips.js` 的 `PRE_RULES`）在录音**之前**扫一遍句子，  
把最容易丢分的词摆出来，最多两条：

```
读之前，留意这几个词
  months  词尾的 -s 一定要读出来，它表示"不止一个"，是丢分最多的地方。
  three   th 要把舌尖轻轻伸到上下牙齿中间，再送气，别读成 s。
```

> ⚠️ 这里和"读错后再解释"用的是**两套规则**。  
> 后解释那套（`RULES`）范围宽一点无所谓；读前预告是主动断言，说错会误导孩子。  
> 实测踩到过：`need` 被当成过去式、`has` 被当成复数、`wear` 被当成读 /iː/。  
> 所以读前那套砍掉了例外太多的拼读组合（ea/ee、oo），`-ed`/`-s`/`wh` 都加了排除词和长度门槛。

### 2. 节奏比对：录音时长 vs 示范时长

`utils/pace.js` 拿孩子的录音时长除以示范音频时长，得到一个比值：

| 比值          | 判定       | 说明                                                |
| ----------- | -------- | ------------------------------------------------- |
| ≤ 0.72      | **读得偏快** | 可靠信号。人不可能读得比示范还快，几乎一定是有词被连读吞掉了                    |
| 0.72 ~ 1.75 | 节奏正常     | 不打扰                                               |
| ≥ 1.75      | 读得偏慢     | 温和提示。**这条不完全可靠**——录音从按下按钮就开始计时，孩子开始前发愣、中间清嗓子都会算进去 |

基准时长来自 `data/audio-length.js`（218 条），由 `tools/gen-audio-length.py` 生成：

```bash
python tools/gen-audio-length.py   # 重新生成（改了音频后要跑）
```

脚本直接遍历 MP3 帧头累加采样数，**不依赖任何解码库**，也不需要 pip 安装东西。

> 踩过的坑：一开始用 `miniaudio` 测时长，在项目目录下（路径含中文）**218 个文件全部报"解码失败"**，  
> 差点误判成音频损坏。实测把文件复制到纯 ASCII 路径就能正常解码 —— 是库读不了中文路径。  
> 改成按字节流解析帧头后，既绕开了这个问题，结果也和实测完全一致（2520ms / 2520ms）。

### 3. 慢速示范

自评面板多了「🐢 慢速示范」，用 `InnerAudioContext.playbackRate = 0.7` 放示范。  
孩子卡在某个词上时，原速听十遍不如慢速听两遍。

## 八、听写：重点句型与单词

朗读考的是"能不能读出来"，听写考的是"能不能写对" —— 是两件事，所以单独做了个模块  
（分包 `dictationAudio/pages/dictation/`，首页有入口）。

> **听写音频单独一套、更清晰**：听写用的示范音频放在分包 `dictationAudio/audios/`，是用更慢的语速（百度 TTS `spd=2`）+ 更高采样率（22kHz）单独合成的，比跟读的 16kHz 音频更清楚；跟读仍用主包 `audios/`，两者互不影响。重新生成见 `tools/gen-dict-audio.js`。

### 题源

| 类型   | 数量       | 来源                                                    |
| ---- | -------- | ----------------------------------------------------- |
| 重点句型 | **41 句** | 各单元 `Grammar in use` 的语法模型句，手工整理进 `data/dictation.js` |
| 单词   | **94 个** | 直接复用 `data/lessons.js` 各单元的课本核心词，不在两处维护同一份词表          |

每句重点句型都标了**语法点**和**易错提醒**，对答案时一起显示：

```
A horse is heavier than me.
马比我重。
语法点：heavy → heavier（辅音+y，变 y 为 i 再加 er）
易错：是 heavier，不是 heavyer
```

### 两种模式

|     | 📝 纸笔听写（默认）                        | ⌨️ 打字听写               |
| --- | ---------------------------------- | --------------------- |
| 怎么做 | 听 → 写在纸上 → 点「对答案」自己核对 → 点"写对了/写错了" | 听 → 输入框打出来 → 点「检查」自动判 |
| 适合  | 学校真实场景。小学生打字慢，默认走这条                | 想精确知道错在哪个字母           |
| 判定  | 孩子自己判                              | 自动逐词判                 |

两种模式都能「再听一遍」「🐢 慢速」，结束后出成绩单，**错题都进同一个错题本**。

### ⚠️ 判分：听写和跟读是两套标准

这是这个模块最容易做错的地方。

|     | 跟读（`utils/score.js`）                     | 听写（`utils/dictation.js`） |
| --- | ---------------------------------------- | ------------------------ |
| 比什么 | 语音**识别出来的文本**                            | 孩子**写出来的拼写**             |
| 匹配  | 模糊匹配，编辑距离 ≤2 算"接近"                       | **只认完全一致**               |
| 为什么 | 语音识别本来就会把 `heavier`/`havier` 听成差不多，太严会冤判 | 听写考的就是拼写，`havier` 必须算错   |

所以 `utils/dictation.js` 自己实现了一遍 **LCS 精确对齐**，而不是复用 `score.js` 的模糊规则。  
这句话在 `tests/dictation.test.js` 里有专门的回归用例。

对齐结果会翻成孩子看得懂的四态标记：

| 标记    | 含义                               |
| ----- | -------------------------------- |
| 绿色    | 写对了                              |
| 红色删除线 | 拼错了（下面还会写"「heavier」写成了「havier」"） |
| 红色波浪线 | 漏写了这个词                           |
| 橙色    | 多写了                              |

> 还有一个容易忽略的坑：`score.js` 归一化时会把 `There is` 合并成 `there's`、`I am` 合并成 `i'm`  
> （为了让跟读的识别结果和课本写法对得上）。判分用它是对的，但**直接显示给孩子就变成了  
> "正确答案写着 I am，批改却在说 i'm"**，看着像批错了。  
> 所以 `score.js` 多了个 `toWordsWithDisplay()`，把归一化后的词再映射回原文写法，专供听写展示用。

### 错题怎么记账

- **和课文原句重合的重点句型，复用课文句子 id**：比如 `We moved here to Shenzhen yesterday.`  
  本身就是课文第 1 句，听写写错时记到的 id 就是 `u1-p1-s1`。  
  这样"朗读也错、听写也错"会**合并成一条**，报告页不会看起来像两个人。  
  （这个 id 不是手写的，是从音频文件名反推的 —— 见 `utils/dictation.js#resolveSourceId`）
- **听写不计入「跟读次数 / 平均分」**：那两个指标的口径保持只讲跟读。听写另有自己的累计正确率，  
  在听写设置页顶部显示。
- **纸笔模式靠 `hardError` 兜底**：纸笔听写没有逐词信息，如果只按"有错词才计错"的规则，  
  孩子自己判的"写错了"会被**静默丢掉**。所以 storage 加了个 `hardError` 标记，  
  表示"确定错了，只是没定位到具体哪个词"。

## 九、示范音频是怎么来的

来源：公开的在线英文发音接口（百度翻译 `gettts`），本地做了一次「解码 → 去首尾静音 → 16kHz 单声道 24kbps 重编码」，  
体积压到原来的 1/4，而且**生成完就随包携带，运行时不再请求任何接口**。

所以：**小程序运行时零网络依赖、零费用、零限额**，音质还比插件 TTS 稳定。

### 改了课文要重新生成音频

```bash
python -m pip install miniaudio lameenc
python tools/gen-audio.py          # 增量：已有音频自动跳过
node tests/audio.test.js           # 校验每一句/每个单词都命中音频
```

想换音色/语速/码率，改 `tools/gen-audio.py` 顶部 CONFIG 区（`TTS_URL` 的 `spd`、`BITRATE`、`SAMPLE_RATE`）。

> 体积参考：24kbps → 1.2MB；16kbps → 0.8MB（音质明显发闷）。小程序主包上限 2MB，当前用 24kbps 很安全。

## 九、怎么加新内容

只需要改 `data/lessons.js`，格式：

{
  id: 'u7', unit: 'Unit 7', en: '…', cn: '…', theme: '#4b6bfb',

## 十一、播放没声音 / 录音没反应？先看这里

### A. 播放没声音

首页有个 **「🔊 音频自检」** 按钮，点一下就能判断是"小程序的问题"还是"手机静音了"。

曾经踩过、已经修掉的三个坑（都写进 `tests/player.test.js` 做回归了）：

| 现象         | 根因                                                                               | 修法                                                                        |
| ---------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 「听示范」没声音   | 代码包内音频用了相对路径 `audios/x.mp3`。`InnerAudioContext` 只认**以 `/` 开头的绝对路径**，传相对路径会静默加载失败 | `utils/audio.js#resolveSrc` 统一补前缀                                         |
| 「听我的」也没声音  | `InnerAudioContext` 默认 `obeyMuteSwitch = true`，**iPhone 打开侧边静音键后完全不出声**（录音不受影响）  | `app.js` 里 `wx.setInnerAudioOption({ obeyMuteSwitch: false })`，每个播放实例再设一次 |
| 出问题页面上毫无反馈 | 播放失败的 `onError` 被吞掉了                                                             | 错误通过 `onError` 冒到页面，toast 出错误码                                            |

播放相关代码**只在 `utils/audio.js` 一处**创建播放器（`tts.js` 和 `asr.js` 都调它），  
好处是天然保证"同一时刻只响一个声音"，也方便以后统一加音量、倍速之类的功能。

如果自检仍然出不了声，按这个顺序排查：


1. **手机音量**，以及 iPhone 侧边的**静音开关**；
2. 是否连着**蓝牙耳机 / 音箱**（声音跑到别的设备去了）；
3. 开发者工具：**设置 → 通用设置 → 声音**，勾上"播放声音"；
4. 真机预览仍无声，把自检弹出的**错误码**记下来对照微信官方 `InnerAudioContext` 错误码表。

### B. 录音没反应

录音失败有两种，**提示语不一样，修法完全不一样** —— 别混。`utils/asr.js` 会自动分辨：

| App 里弹出                 | 真正的原因                         | 怎么修                                                                                        |
| ----------------------- | ----------------------------- | ------------------------------------------------------------------------------------------ |
| **「录音还不能用」**（说明后台配置的弹窗） | 小程序后台**没在《用户隐私保护指引》里声明「麦克风」** | 管理员登录 mp.weixin.qq.com → 设置 → 服务内容声明 → 用户隐私保护指引 → 勾选「麦克风」→ 提交。详见 [发布上线指南.md](发布上线指南.md) A0 |
| **「需要麦克风权限」**（带"去设置"按钮） | 用户自己拒绝过录音权限                   | 点"去设置"打开，或小程序右上角「…」→ 设置 → 打开「录音」                                                           |

> 第一种是最坑的：它是**账号后台配置**问题，不是手机问题。  
> 表现是"代码不报错、弹窗不出现、录音就是没反应"，  
> 而且点"去设置"也找不到录音开关（没声明就不会出现这个开关）。  
> 所以这里**绝不能**统一提示"去设置" —— 那会把家长带进死胡同。  
> `tests/privacy.test.js` 专门盯住这两个分支不许写混。

## 十二、已知限制与后续可做

- **自评模式没有机器判定**：这是个人主体的取舍。想自动打分就走 `cloud` 模式。
- **评分定位**：即使是云端模式，当前也是"识别文本比对"，能抓发音造成的内容错误，但**不是专业音素级评测**。  
  若要逐音素打分（讯飞 / 腾讯智聆口语评测），新增一个 `utils/evaluate.js` 适配层，  
  把 `handleAutoResult` 的数据源换掉即可，页面不用动。
- **音频版权提醒**：`audios/` 里的示范音频由公开 TTS 接口生成，仅用于家庭教育场景，  
  不要用于商业分发；如果是正式出版物配套，建议换成出版社授权的原版录音。
- **可选增强**：课本原版录音随包播放（`utils/tts.js` 已有 `playFile`）、生词本导出、家长端周报、云开发同步。
